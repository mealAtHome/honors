# 모임은야구 개발 로드맵

다른 컴퓨터나 새 세션에서 개발을 이어가기 위한 문서다. 작업을 끝낼 때마다 아래 "진행 현황"을 갱신한다.
기능 목록은 `honors-docs/기능일람표.xlsx`(관점 → 메뉴 → 화면 계단식, 비고에 미완성·버그 기록)를 기준으로 한다.

## 사용 관점

| 관점 | 설명 | 화면 |
|---|---|---|
| 유저 | 모임에 참가하고 일정 신청·정산을 하는 일반 회원 | A00~A15, D10, F00, G00, Z00 |
| 모임 관리자 | 모임장·부매니저. 일정·정산·멤버·재무 관리 | B00~B88, B1000~, B70~, F10 |
| 플랫폼 관리자 | 서비스 운영자(`user.adminflg='y'`). 화면은 아직 없음, 추가 예정 | (없음) |

## 단계별 방향 (2026-11-03 결정)

### 1단계 — 고객층 확장: 용병야구, 일반 팀, 일반 모임
- 기능일람표 비고의 미완성 기능부터 개발한다(아래 1단계 백로그).
- 모임생성 기능을 개발한다. 미등록 화면 `B01-ManagerRegist.html`을 다시 쓰는 것을 검토.
- 모임 타입(용병 / 팀 / 모임)을 지정할 수 있게 한다. 타입에 따라 가입 방식이 달라질 수 있으므로 가입 흐름과 함께 설계.
- 설계 결정(2026-11-03): 타입은 속성의 기본값 묶음(프리셋)으로 둔다. 속성 = 가입 방식(승인/자유/가입 없음), 일정 공개 범위(멤버만/외부 신청 허용), 회비 방식(정기/일정별), 한 일정의 라인업 수.
  - 용병은 **일정 속성(외부 참가 허용 + 모집 인원)과 모임 타입(모든 일정이 기본 공개) 둘 다**로 지원한다. 팀이 특정 시합에 용병을 구하는 경우가 가장 흔하기 때문.
  - 용병 모집도 1단계에 포함하기로 결정(2026-11-03). 비멤버 용병은 신청 시 그 모임에 **게스트 멤버(`grp_member.grpmtype = 'guest'`)**로 자동 등록해 정산·잔여금·기록을 기존 구조로 처리한다. 게스트는 멤버수 집계와 멤버 권한(`GGauth::isGrpmember`)에서 빠진다.
  - 회비 방식, 한 일정의 라인업 수는 아직 동작이 없어 컬럼을 만들지 않았다(필요해질 때 추가).

### 1-1단계 — 임시유저 기능 강화
- 앱에 가입하지 않은 지인도 현장 참가·기록 연동을 위해 임시유저로 관리한다.
- 임시유저는 모임 안에서 관리하고, 실제로 가입하면 그 유저에 병합한다.
- 서버는 이미 있음: `GrpMemberBO::makeTempUserForMng`, `mergeTempToMemberForMng`. 화면 진입(S10 임시멤버 탭, B71 병합 버튼)이 주석 처리되어 있다.
- 4단계 기록의 주체가 될 수 있게 설계한다(병합 시 기록도 함께 이관).

### 2단계 — 정산 재정비
- 일정마다 수동정산 / 자동정산을 선택해 만든다.
  - 수동정산: 지금 방식. 직접 정산하고 입금확인도 수동.
  - 자동정산: PG 연동으로 계산과 정산을 자동 처리.
- 모든 결제는 관리자 계좌로 들어왔다가 관리자가 각 모임에 정산하는 구조.
- 주의: 타인의 돈을 받아 대신 정산하는 구조는 전자금융거래법상 결제·정산대행 규제 대상일 수 있다. PG사의 오픈마켓/하위몰 정산 상품과 법률 검토를 설계 전에 확인할 것.

### 3단계 — PC 웹
- `honors-main`에서 모든 유저가 PC로 같은 기능을 쓰게 한다.
- `honors-script`의 API 래퍼(`Api.*`, `ApiPr.*`)와 모델의 데이터·getter는 재사용 대상으로 설계되어 있다.
- 단, 모델의 `make()`는 모바일 HTML과 `Navigation.Page`를 직접 만든다(예: `MCls.js` `make()`). 새 모델은 화면 렌더링을 모델 밖으로 분리해 두면 이관이 쉽다.

### 4단계 — 기록 기능
- 참가자 목록(기록용 인원 추가 가능)으로 경기 기록을 작성한다.
- 모임 관리자는 일정에서 기록을 쓰거나, 일정 없이도 기록을 등록할 수 있다.
- 기록 테이블은 `clsno` 없이도, 리그 키로도 쓸 수 있는 구조로 처음부터 잡는다.

### 5단계 — 리그 관리자
- 리그를 만들고, 현장 기록지로 기록을 작성·조회한다.
- AI 에이전트로 기록지(사진 등)를 기록 데이터로 옮긴다.
